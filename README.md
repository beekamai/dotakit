## English

Typed client for the **Dota 2 Game Coordinator** — the hello/welcome handshake, a message
router and promise-based request/response jobs, on top of any Steam connection you already
have. Bun-first, ships ESM + CJS + type declarations, and the whole protocol surface is
generated from Valve's protobufs.

It does not log into Steam. Bring your own `steam-user` (or anything that satisfies the
`SteamTransport` interface) and this library takes over from there.

### Features

- 🤝 **Handshake that heals itself** — hello on app launch, exponential backoff, automatic re-hello whenever the GC drops the session.
- 🧾 **Typed message maps** — 486 message ids wired to their protobuf codecs, 137 request/response pairs, generated by a script you can re-run.
- ⏱️ **Jobs that never hang** — `sendJob` always settles: decoded reply, timeout, abort, session loss, or an error **with the raw bytes attached**. A reply with the wrong message id is refused, not decoded into a plausible-looking object.
- 📮 **Router that never drops** — unknown message ids surface on `unknown`, malformed payloads on `decodeError`, everything on `onAny`.
- 🔌 **Transport-agnostic** — a `steam-user` instance satisfies the interface as-is; tests run against a fake with no network and no real time.
- 🧪 **Tested offline** — 51 tests over the handshake timings, job lifecycle and routing, driven by an injectable clock.

### Quick start

```bash
bun add dota2-gc      # or: npm install dota2-gc / pnpm add dota2-gc
```

Works on **Node 18+** and **Bun**.

```ts
import SteamUser from "steam-user";
import { Dota2GC, EDOTAGCMsg } from "dota2-gc";

const steam = new SteamUser();
const gc = new Dota2GC(steam, { autoGamesPlayed: true });

steam.logOn({ accountName: "…", password: "…" });
await new Promise((resolve) => steam.once("loggedOn", resolve));

const welcome = await gc.connect({ timeoutMs: 30_000 });
console.log("GC session, version", welcome.version);

// Request/response as a promise — typed from the message id
const guild = await gc.sendJob(EDOTAGCMsg.k_EMsgClientToGCRequestGuildData, { guildId: 1234 });
console.log(guild.guildData?.guildMembers.length, "members");

// Fire-and-forget plus a listener, for pushes the GC sends on its own
gc.router.on(EDOTAGCMsg.k_EMsgGCToClientGuildMembersDataUpdated, (update) => {
    console.log("members changed", update.guildId);
});
```

`connect()` resolves on the **first** session. The `connected` event fires on **every**
session, including reconnects — the GC drops clients routinely (restarts, logon queue,
suspension) and the handshake restarts on its own. Re-subscribe your state in `connected`,
not after `connect()`.

### API

| Member | What it does |
|---|---|
| `new Dota2GC(steam, options?)` | Hooks the transport and starts watching for the app launch. |
| `connect({ timeoutMs? })` | Promise for the GC welcome. Resolves at once if a session exists. |
| `disconnect()` | Stops the handshake, forgets the session, rejects in-flight jobs, keeps the transport hooked. |
| `destroy()` | `disconnect()` plus: detach transport listeners, reject in-flight jobs. |
| `send(msgId, partialBody)` | Encodes via `fromPartial` and sends. Every field optional. |
| `sendJob(msgId, partialBody, opts?)` | Sends and resolves with the decoded reply. |
| `sendRaw(msgId, buffer, cb?)` | Sends already-encoded bytes. |
| `sendJobRaw(msgId, buffer, opts?)` | Raw bytes in, raw reply bytes out. |
| `router` | The `GCRouter` for inbound traffic. |
| `haveGCSession` / `inApp` / `welcome` | Current state. |
| `on("connected" \| "disconnected", …)` | Session events. |

`Dota2GCOptions`: `appid` (570), `autoGamesPlayed` (false), `jobTimeoutMs` (10000),
`helloInitialMs` (500), `helloBaseMs` (1000), `helloBackoffMaxMs` (60000), `logger`, `timers`.

`JobOptions`: `timeoutMs` (`0` waits forever; negative or `NaN` is rejected, not silently
infinite), `signal`, `responseId` (decode the reply with a specific message id, which also
waives the expected-response check).

| `GCRouter` member | What it does |
|---|---|
| `on(msgId, handler)` | Decoded payload, typed from the numeric message id. |
| `once` / `off` / `removeAllListeners` | The usual emitter surface, keyed by message id. |
| `onAny(handler)` / `offAny` | Every routed message: decoded when possible, raw otherwise. |
| `on("unknown", (msgId, buffer))` | Inbound ids with no codec — never silently dropped. |
| `on("decodeError", (msgId, buffer, err))` | Malformed payload. `route()` never throws on bad input. |
| `hasDecoder(msgId)` / `messageName(msgId)` | Introspection. |

Errors — all extend `Dota2GCError`:

| Error | When |
|---|---|
| `NotConnectedError` | Sending while Steam is not logged in or after `destroy()`; a job or a pending `connect()` cut short by session loss or `destroy()`. |
| `NoEncoderError` | No codec for the outgoing message id. |
| `NoDecoderError` | Reply id has no codec. Carries `msgId` and the raw `payload`. |
| `UnexpectedResponseError` | The GC answered with an id other than the one `jobResponses` expects. Carries both ids and the raw `payload`. Override with `responseId`. |
| `JobTimeoutError` | Deadline passed with no reply. |
| `JobAbortedError` | The `AbortSignal` fired; the reason is in `cause`. |

### Message maps

Generated into `src/messages.ts` and exported from the package root:

| Export | Contents |
|---|---|
| `clientMessages` | 250 ids a client sends. |
| `gcMessages` | 236 ids the GC sends. |
| `allMessages` | Both, 486 ids in total. |
| `jobResponses` | 137 request id → response id pairs. |
| `messageNames` | Numeric id → `k_EMsg…` enum member name. |

The enums themselves — `EDOTAGCMsg`, `EGCBaseClientMsg`, `ESOMsg`, `EGCBaseMsg`,
`GCConnectionStatus` — are re-exported from the root too. Every generated message **type**
lives behind the `dota2-gc/protobufs` subpath:

```ts
import type { CMsgDOTAProfileCard, CSourceTVGameSmall } from "dota2-gc/protobufs";
```

### Migrating from `dota2-user`

| `dota2-user` | `dota2-gc` |
|---|---|
| `new Dota2User(steam)` | `new Dota2GC(steam, options?)` |
| `"connectedToGC"` | `"connected"` (payload: the welcome message) |
| `"disconnectedFromGC"` | `"disconnected"` |
| `sendPartial(id, body)` | `send(id, body)` — always partial, there is no strict variant |
| `send(id, fullBody)` | `send(id, body)` |
| `sendRawBuffer(id, buf, cb)` | `sendRaw(id, buf, cb)` / `sendJobRaw(id, buf)` |
| `sendJob(id, body): Promise<unknown>` | `sendJob(id, body, opts?)` — typed reply, timeout, `AbortSignal` |
| `inDota2` | `inApp` |
| `router.route` / `router.on` | same, plus `unknown`, `decodeError`, `offAny` |
| `Dota2User.STEAM_APPID` | `DOTA2_APPID`, or `options.appid` |
| `Dota2UserError` | `Dota2GCError` and its subclasses |

Behavioural differences worth knowing:

- A job whose reply has no codec **rejects with `NoDecoderError`** (raw bytes attached) instead of hanging until the timeout; a reply with an unexpected id rejects with `UnexpectedResponseError` rather than being decoded as the expected type.
- Losing the GC session rejects every in-flight job at once instead of leaving each to run out its own timeout.
- The router reports unknown ids and decode failures instead of logging and returning.
- The hello backoff is `helloInitialMs` → `helloBaseMs` → doubling → `helloBackoffMaxMs`, so the first retry is 1 s rather than 2 s.
- Steam is not validated: any `SteamTransport` works, `steam-user` is not a dependency.

### Regenerating the protobufs

The generated output is committed, so installing this package never runs `protoc`. Refresh
it when Valve ships new GC messages:

```bash
bun add -d ts-proto            # protoc must already be on PATH
bun run gen:protos             # clones SteamDatabase/Protobufs, regenerates src/protobufs
bun run gen:messages           # rebuilds src/messages.ts from the new enums
bun test && bunx tsc --noEmit
```

`scripts/gen-protos.ts` shells out to:

```bash
protoc --plugin=protoc-gen-ts_proto=node_modules/.bin/protoc-gen-ts_proto \
       --ts_proto_out=src/protobufs \
       --ts_proto_opt=esModuleInterop=true,forceLong=string,outputIndex=true,outputServices=false,useOptionals=none,unrecognizedEnum=false \
       -I dota2 -I . <entry .proto files>
```

`scripts/gen-messages.ts` then scans that output: it reads the four message-id enums, pairs
each `k_EMsg<Name>` with the exported `CMsg<Name>` codec (trying the `GC`/`DOTA` infix
spellings Valve uses inconsistently), derives `<Name>Response` and `ClientToGC…` →
`GCToClient…Response` pairs, and applies `scripts/overrides.json` for the irregular ones
(the base-client handshake, the SO cache messages, `GetProfileCardResponse` →
`CMsgDOTAProfileCard`). It prints coverage counts so a regression is visible.

## Русский

Типизированный клиент **Game Coordinator Dota 2** — хендшейк hello/welcome, роутер сообщений
и request/response через промисы, поверх любого уже установленного соединения со Steam. На
Bun, поставляется ESM + CJS + декларации типов, вся поверхность протокола генерируется из
протобафов Valve.

Логином в Steam библиотека не занимается. Приносите свой `steam-user` (или что угодно,
удовлетворяющее интерфейсу `SteamTransport`) — дальше работает она.

### Возможности

- 🤝 **Самовосстанавливающийся хендшейк** — hello при запуске приложения, экспоненциальный бэкофф, автоматический re-hello, когда GC роняет сессию.
- 🧾 **Типизированные карты сообщений** — 486 id связаны с кодеками, 137 пар request/response, генерируются скриптом, который можно перезапустить.
- ⏱️ **Джобы, которые не висят** — `sendJob` всегда завершается: разобранный ответ, таймаут, отмена, потеря сессии или ошибка **с приложенными сырыми байтами**. Ответ с чужим id отклоняется, а не разбирается в правдоподобный объект.
- 📮 **Роутер, который ничего не теряет** — неизвестные id идут в `unknown`, битые payload'ы в `decodeError`, всё подряд — в `onAny`.
- 🔌 **Транспорт-агностик** — инстанс `steam-user` подходит как есть; тесты гоняются на фейке без сети и без реального времени.
- 🧪 **Тесты офлайн** — 51 тестов на тайминги хендшейка, жизненный цикл джоб и роутинг, на подменяемых часах.

### Быстрый старт

```bash
bun add dota2-gc      # либо: npm install dota2-gc / pnpm add dota2-gc
```

Работает на **Node 18+** и **Bun**.

```ts
import SteamUser from "steam-user";
import { Dota2GC, EDOTAGCMsg } from "dota2-gc";

const steam = new SteamUser();
const gc = new Dota2GC(steam, { autoGamesPlayed: true });

steam.logOn({ accountName: "…", password: "…" });
await new Promise((resolve) => steam.once("loggedOn", resolve));

const welcome = await gc.connect({ timeoutMs: 30_000 });
console.log("сессия GC, версия", welcome.version);

// Request/response промисом — тип ответа выводится из id сообщения
const guild = await gc.sendJob(EDOTAGCMsg.k_EMsgClientToGCRequestGuildData, { guildId: 1234 });
console.log(guild.guildData?.guildMembers.length, "участников");

// Отправка без ответа плюс слушатель — для пушей, которые GC шлёт сам
gc.router.on(EDOTAGCMsg.k_EMsgGCToClientGuildMembersDataUpdated, (update) => {
    console.log("состав изменился", update.guildId);
});
```

`connect()` резолвится на **первой** сессии. Событие `connected` срабатывает на **каждой**,
включая переподключения: GC роняет клиентов регулярно (рестарты, очередь логона,
suspension), и хендшейк перезапускается сам. Переподписывайте состояние в `connected`, а не
после `connect()`.

### API

| Член | Что делает |
|---|---|
| `new Dota2GC(steam, options?)` | Вешает хуки на транспорт и ждёт запуска приложения. |
| `connect({ timeoutMs? })` | Промис с welcome от GC. Резолвится сразу, если сессия уже есть. |
| `disconnect()` | Останавливает хендшейк, забывает сессию, реджектит незавершённые джобы, хуки транспорта оставляет. |
| `destroy()` | `disconnect()` плюс: снять хуки, отклонить незавершённые джобы. |
| `send(msgId, partialBody)` | Кодирует через `fromPartial` и отправляет. Все поля опциональны. |
| `sendJob(msgId, partialBody, opts?)` | Отправляет и резолвится разобранным ответом. |
| `sendRaw(msgId, buffer, cb?)` | Отправляет уже закодированные байты. |
| `sendJobRaw(msgId, buffer, opts?)` | Сырые байты внутрь, сырые байты ответа наружу. |
| `router` | `GCRouter` для входящего трафика. |
| `haveGCSession` / `inApp` / `welcome` | Текущее состояние. |
| `on("connected" \| "disconnected", …)` | События сессии. |

`Dota2GCOptions`: `appid` (570), `autoGamesPlayed` (false), `jobTimeoutMs` (10000),
`helloInitialMs` (500), `helloBaseMs` (1000), `helloBackoffMaxMs` (60000), `logger`, `timers`.

`JobOptions`: `timeoutMs` (`0` — ждать вечно; отрицательное или `NaN` отклоняется, а не
считается бесконечностью), `signal`, `responseId` (разобрать ответ конкретным id сообщения —
заодно снимает проверку ожидаемого ответа).

| Член `GCRouter` | Что делает |
|---|---|
| `on(msgId, handler)` | Разобранный payload, тип выводится из числового id. |
| `once` / `off` / `removeAllListeners` | Обычная поверхность эмиттера по id сообщения. |
| `onAny(handler)` / `offAny` | Каждое сообщение: разобранное, если возможно, иначе сырое. |
| `on("unknown", (msgId, buffer))` | Входящие id без кодека — молча не теряются. |
| `on("decodeError", (msgId, buffer, err))` | Битый payload. `route()` не бросает на плохом вводе. |
| `hasDecoder(msgId)` / `messageName(msgId)` | Интроспекция. |

Ошибки — все наследуют `Dota2GCError`:

| Ошибка | Когда |
|---|---|
| `NotConnectedError` | Отправка без логина в Steam или после `destroy()`; джоба или ждущий `connect()`, оборванные потерей сессии либо `destroy()`. |
| `NoEncoderError` | Нет кодека для исходящего id. |
| `NoDecoderError` | У id ответа нет кодека. Несёт `msgId` и сырой `payload`. |
| `UnexpectedResponseError` | GC ответил id, отличным от ожидаемого по `jobResponses`. Несёт оба id и сырой `payload`. Переопределяется через `responseId`. |
| `JobTimeoutError` | Дедлайн истёк, ответа нет. |
| `JobAbortedError` | Сработал `AbortSignal`; причина — в `cause`. |

### Карты сообщений

Генерируются в `src/messages.ts` и экспортируются из корня пакета:

| Экспорт | Содержимое |
|---|---|
| `clientMessages` | 250 id, которые шлёт клиент. |
| `gcMessages` | 236 id, которые шлёт GC. |
| `allMessages` | И то и другое, 486 id. |
| `jobResponses` | 137 пар «id запроса → id ответа». |
| `messageNames` | Числовой id → имя члена перечисления `k_EMsg…`. |

Сами перечисления — `EDOTAGCMsg`, `EGCBaseClientMsg`, `ESOMsg`, `EGCBaseMsg`,
`GCConnectionStatus` — тоже реэкспортируются из корня. Все сгенерированные **типы**
сообщений живут в сабпасе `dota2-gc/protobufs`:

```ts
import type { CMsgDOTAProfileCard, CSourceTVGameSmall } from "dota2-gc/protobufs";
```

### Миграция с `dota2-user`

| `dota2-user` | `dota2-gc` |
|---|---|
| `new Dota2User(steam)` | `new Dota2GC(steam, options?)` |
| `"connectedToGC"` | `"connected"` (в payload — welcome) |
| `"disconnectedFromGC"` | `"disconnected"` |
| `sendPartial(id, body)` | `send(id, body)` — всегда partial, строгого варианта нет |
| `send(id, fullBody)` | `send(id, body)` |
| `sendRawBuffer(id, buf, cb)` | `sendRaw(id, buf, cb)` / `sendJobRaw(id, buf)` |
| `sendJob(id, body): Promise<unknown>` | `sendJob(id, body, opts?)` — типизированный ответ, таймаут, `AbortSignal` |
| `inDota2` | `inApp` |
| `router.route` / `router.on` | то же, плюс `unknown`, `decodeError`, `offAny` |
| `Dota2User.STEAM_APPID` | `DOTA2_APPID` либо `options.appid` |
| `Dota2UserError` | `Dota2GCError` и наследники |

Различия в поведении, о которых стоит знать:

- Джоба, у ответа которой нет кодека, **реджектится `NoDecoderError`** (с сырыми байтами), а не висит до таймаута; ответ с неожиданным id реджектится `UnexpectedResponseError`, а не разбирается ожидаемым типом.
- Потеря сессии GC реджектит все незавершённые джобы сразу, а не оставляет каждую досиживать свой таймаут.
- Роутер сообщает о неизвестных id и об ошибках разбора вместо «залогировать и выйти».
- Бэкофф hello: `helloInitialMs` → `helloBaseMs` → удвоение → `helloBackoffMaxMs`, то есть первый ретрай через 1 с, а не через 2 с.
- Steam не валидируется: подходит любой `SteamTransport`, `steam-user` не является зависимостью.

### Перегенерация протобафов

Сгенерированный вывод закоммичен, поэтому установка пакета никогда не запускает `protoc`.
Обновляйте, когда Valve завозит новые сообщения GC:

```bash
bun add -d ts-proto            # protoc должен уже быть в PATH
bun run gen:protos             # клонирует SteamDatabase/Protobufs, генерит src/protobufs
bun run gen:messages           # пересобирает src/messages.ts по новым перечислениям
bun test && bunx tsc --noEmit
```

`scripts/gen-protos.ts` вызывает:

```bash
protoc --plugin=protoc-gen-ts_proto=node_modules/.bin/protoc-gen-ts_proto \
       --ts_proto_out=src/protobufs \
       --ts_proto_opt=esModuleInterop=true,forceLong=string,outputIndex=true,outputServices=false,useOptionals=none,unrecognizedEnum=false \
       -I dota2 -I . <входные .proto>
```

Дальше `scripts/gen-messages.ts` сканирует вывод: читает четыре перечисления id, сопоставляет
каждый `k_EMsg<Name>` с экспортированным кодеком `CMsg<Name>` (перебирая варианты написания с
инфиксами `GC`/`DOTA`, которые Valve ставит непоследовательно), выводит пары `<Name>Response`
и `ClientToGC…` → `GCToClient…Response` и применяет `scripts/overrides.json` для нерегулярных
случаев (базовый хендшейк, сообщения SO-кеша, `GetProfileCardResponse` →
`CMsgDOTAProfileCard`). Он печатает счётчики покрытия, так что регрессия видна сразу.
